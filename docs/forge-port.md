# Forge 1.20.1 port verification

The reference is NuclearCraft: Overhauled 2o.9.7 at `ef28c65`. The port builds with Java 17, Mojang mappings, and Forge 47.4.10, matching the Forge build installed in Auram. The Forge code currently comes from the legacy NuclearCraft source and uses no Neohaul implementation code.

## Gameplay coverage

- The Melter has an in-world block, menu, datapack recipes for ice, packed ice, and sulfur dust, and a Forge fluid registration for molten sulfur.

## Verified with Auram mod JARs

A disposable headless Forge 47.4.10 server ran the reobfuscated NuclearCraft JAR with the exact Ender IO and Mekanism JARs from Auram. Each Melter received one ice and 4,000 FE. Server block data confirmed both destinations held exactly 1,000 mB of water and both Melter output tanks were empty.

- Melter → Ender IO Fluid Conduit → Ender IO Fluid Tank
- Melter → Mekanism Basic Mechanical Pipe in pull mode → Ender IO Fluid Tank

The same packaged reactor ran with each mod's pipes at both vents. Each setup emptied a 1,000 mB source tank, delivered 4,000 mB of high-pressure steam to its destination, and produced one depleted fuel item. The two devices were Ender IO Fluid Conduits and Mekanism Basic Mechanical Pipes, using Ender IO 8.2.17-beta and Mekanism 10.4.16.80. A full restart of the same test world preserved the steam volumes and depleted fuel in both setups.

### Terrain radiation and Wasteland mapping

The legacy default is zero. At or above 10 Rad/t, soil can become Wasteland Earth. Leaves and vines disappear from 1 Rad/t, and saplings can become dead bushes from 4 Rad/t. Wasteland Earth can recover into dirt below 0.001 Rad/t, including once contamination has decayed to zero. Terrain recipes leave block entities intact.

The Wasteland maps newly generated chunks after feature placement. Soil becomes coarse dirt, leaves and doors decay, trapped water is drained, and some glass, wool, and timber decay. The `nuclearcraft:wasteland_preserved` block tag extends the default protections. The `wasteland_mapping_enabled` and `wasteland_mapping_chunks_per_tick` settings are in `world/serverconfig/nuclearcraft-wasteland.toml`. The default tick cap is eight. A value of zero processes one newly generated chunk per tick because Forge exposes those chunks after generation through its load lifecycle. Pending work persists on disk, and completed chunks keep player edits across restarts and subsequent generation. [Forge chunk lifecycle](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.20.1/src/main/java/net/minecraftforge/event/level/ChunkEvent.java)

Migrate terrain scripts to the Forge recipe types `nuclearcraft:radiation_block_mutation`, `nuclearcraft:radiation_block_purification`, or `nuclearcraft:wasteland_block_mapping`. Put the JSON under `data/<namespace>/recipes/` or add the same object with KubeJS `event.custom`. The `input` object takes a `block` or `tag` registry ID and optional `properties` with block-state value strings. The `result` object takes a `block` and optional state `properties`. Use `radiation_threshold` for the rate in Rad/t. Higher `priority` values take precedence, with ties resolved by recipe ID. Map legacy metadata and ore dictionary aliases to state properties and block tags. [Forge custom recipes](https://docs.minecraftforge.net/en/1.20.1/resources/server/recipes/custom/)

### Glowing mushrooms

The small crop keeps the `nuclearcraft:glowing_mushroom` ID and its RadAway recipes. It grows on sturdy blocks at any light level and spreads while fewer than five glowing mushrooms occupy its local spread area. It also joins `forge:mushrooms` for pack recipes. World generation and bonemeal use the `nuclearcraft:glowing_mushroom_biomes` biome tag, which includes Nuclear Wasteland and the Nether. A successful bonemeal roll grows the original flat cap or hollow dome. Both blocks emit light level 15. Breaking a giant block has the original one-in-nine chance of dropping a small mushroom, and Silk Touch harvests the giant block.

Copy `mushroom_spread_rate`, `mushroom_gen`, `mushroom_gen_size`, and `mushroom_gen_rate` to `config/nuclearcraft-wasteland-worldgen.toml`. Their defaults are 16, true, 32, and 64. Saved giant blocks use the `variant` property on `nuclearcraft:glowing_mushroom_block`. Legacy metadata 1–9 map in order to `north_west`, `north`, `north_east`, `west`, `center`, `east`, `south_west`, `south`, and `south_east`. Metadata 0, 10, 14, and 15 map to `all_inside`, `stem`, `all_outside`, and `all_stem`.

The growth and state migration follow Overhauled 2o.9.7. Neohaul's feature selection and Neoteric's Forge 1.20 block were checked as references. ### Wasteland vaults

Operators can run `/nc_generate_vault` at their position or use `/execute positioned … run nc_generate_vault` from the console. The command searches for a clear surface entrance and uses village piece bounds where a village starts in the selected chunk. The procedural structure includes the standard and deep sectors, concrete and terracotta palettes, furnished rooms, Nuclear Furnace benches, corridors, spiral stairs, ladder shafts, and the hidden shaft leading to the unique deep loot room. [Forge command registration](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.20.1/src/main/java/net/minecraftforge/event/RegisterCommandsEvent.java)

The Wasteland generator uses the legacy per-chunk seed and one-in-two roll at valid village starts. Other eligible biome chunks use the one-in-8,192 roll. The `nuclearcraft:natural_vaults` biome tag controls the sparse route, and the world’s Generate Structures setting controls both routes. Natural entrances use the terrain height prediction and village building bounds available during Forge structure generation. [Forge chunk lifecycle](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.20.1/src/main/java/net/minecraftforge/event/level/ChunkEvent.java)

Rooms within eight chunks generate through Forge’s normal structure references. The Wasteland saves large vault layouts in `data/nuclearcraft_vault_overflow.dat` so farther rooms can appear when their own chunks load. Each completed portion saves its placement marker alongside its blocks and chest data in that chunk. Wasteland terrain mapping preserves vault pieces, including pieces outside the native reference range. [Forge Saved Data](https://docs.minecraftforge.net/en/1.20.1/datastorage/saveddata/)

Manual generation writes the complete layout across intersecting chunks and records the registered `nuclearcraft:wasteland_vault` start. Forge serializes standard references within eight chunks of the start. The complete piece list and all generated blocks persist for longer layouts. To migrate old structure metadata, convert `NuclearCraftVault` and `NuclearCraftVaultComponent` to `nuclearcraft:wasteland_vault` and `nuclearcraft:vault_piece` and convert the old piece block metadata to Forge 1.20.1 block states. The new pieces retain the legacy `Type`, `Doors`, `SurfaceY`, `RoomType`, and `SectorType` fields.

The loot table keeps the `nuclearcraft:chests/vault` ID and all three legacy pools. The flat item IDs include Heavy Radiation Shielding, an enchanted golden apple, Plutonium-238, Californium-250, and a Forge Roentgen Josh Bucket. Pikelet, Congress Tart, Ricecake, and the craftable Fish and a Ricecake keep their original food values, effects, and textures.

### Nuclear Furnace

The block, item, block entity, and menu use `nuclearcraft:nuclear_furnace`. The original recipe surrounds a furnace with Basic Plating at the corners and Tough Alloy along the edges. The Nuclear Furnace uses the server's `minecraft:smelting` recipes and displays them through JEI's smelting category. It cooks one input in ten ticks, preserves recipe output counts, and ignites fresh fuel only when a recipe result can fit. Forge-tagged uranium ingots and dusts burn for 320 ticks and uranium storage blocks burn for 3,200 ticks. The furnace emits the legacy LEU-235 fission radiation rate during its burn. [Forge furnace support](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.20.1/patches/minecraft/net/minecraft/world/level/block/entity/AbstractFurnaceBlockEntity.java.patch)

Automation inserts the smelting input from above, inserts uranium from the sides or below, and extracts products from the sides or below. The Nuclear Furnace uses Forge's sided item handlers and vanilla furnace result slots, including recipe experience for players. The port follows the original 2o.9.7 timings and routing. The Neohaul furnace and Neoteric processor capabilities served as modern references. [Neohaul Nuclear Furnace](https://github.com/nathanrreed/Nuclearcraft-Neohaul/blob/a2b4bb7/src/main/java/com/nred/nuclearcraft/block_entity/processor/NuclearFurnaceEntity.java), [Neoteric processor block entity](https://github.com/igentuman/NuclearCraft-Neoteric/blob/f19e07a/src/main/java/igentuman/nc/block/entity/processor/NCProcessorBE.java), [Forge capability lifecycle](https://docs.minecraftforge.net/en/1.20.1/datastorage/capabilities/)

Block metadata values 2–5 map to north, south, west, and east, and bit 8 maps to `lit`. The block entity reads legacy `furnaceBurnTime`, `currentItemBurnTime`, and `cookTime` when loading converted inventory data. The ten-tick cook total is fixed. The numeric radiation field is recalculated from burn time.

### Feral and glowing ghouls

The legacy entity IDs are `nuclearcraft:feral_ghoul` and `nuclearcraft:glowing_ghoul`. Their modern spawn eggs use the matching `_spawn_egg` IDs. The Nuclear Wasteland biome spawns feral ghouls in daylight and glowing ghouls underground where the chunk radiation exceeds the legacy background threshold. Both use the original model, adult proportions, wall climbing, husk loot, and charge and death sounds. Feral ghouls can leap at nearby targets. Glowing ghouls use the original emissive layer. The dimension plays its nine original ambient tracks on the music channel.

Feral and glowing attacks add 0.33 and 3.8 Rad respectively at the base difficulty multiplier. Successful attacks on nonhostile living targets inflict poison and add radiation to the victim's buffered exposure. The amount increases with local difficulty and absorbs over `radiation_poison_time`. The two legacy attack settings retain their names in `world/serverconfig/nuclearcraft-radiation.toml`. Ghouls retain radiation buffs at a fatal dose. Villagers and other NPCs can convert to feral ghouls at a fatal dose or on entering the Wasteland. Conversion preserves their name, AI setting, and persistence and uses Forge's conversion and spawn events.

Move the two `register_entity` booleans to `world/serverconfig/nuclearcraft-entities.toml`, in feral then glowing order. Registered entity IDs remain available to saves and datapacks. A disabled type cannot spawn naturally and discards any loaded instances. The legacy 64-block default tracking range maps to four Forge tracking chunks.

### Radiation Scrubber

The block, item, recipe type, and menu use `nuclearcraft:radiation_scrubber`. It reserves the inputs for a batch and keeps them, along with partial progress, when the chunk unloads or the server stops. With output set to Hold, a full output tank or slot stops energy use and radiation removal. The redstone control in the menu enables pausing when powered. Sneak-use the block with an empty hand to read its measured removal rate and effective efficiency.

| Medium | Consumed | Produced | Ticks | FE/t | Efficiency |
| --- | --- | --- | ---: | ---: | ---: |
| Borax | 1 borax | 1 irradiated borax | 12,000 | 200 | 100% |
| RadAway | 250 mB RadAway | 250 mB ethanol | 2,400 | 40 | 500% |
| Slow RadAway | 250 mB Slow RadAway | 250 mB redstone ethanol | 96,000 | 20 | 25% |

The `radiation_scrubber_time`, `radiation_scrubber_power`, and `radiation_scrubber_efficiency` arrays map to `ticks`, `energy_per_tick`, and `efficiency` under `scrubber.borax`, `scrubber.radaway`, and `scrubber.slow_radaway` in `world/serverconfig/nuclearcraft-radiation.toml`. The nonlinear curve's four values map in order to `scrubber.curve_base`, `scrubber.curve_divisor`, `scrubber.curve_scale`, and `scrubber.curve_root`. The radius, linear fraction, and nonlinear switch keep their original names. Nearby full collision blocks, including glass, reduce efficiency using the legacy distance and overlap weights. The old environment registry tracked only one position per Scrubber, so the port measures the loaded area directly.

A datapack or KubeJS recipe can choose a stock `medium` or supply its own `ticks`, `energy_per_tick`, and `efficiency`. Supply at least one of `item_input` and `fluid_input` and at least one of `item_output` and `fluid_output`. These use a counted Forge ingredient, a fluid ID or tag and amount, an item stack, and a fluid stack respectively. Converted Scrubber saves need to map input and output inventories, both tanks, the reserved media, recipe ID, and progress into the Forge block entity. The `redstoneControl` flag retains its key.
